======================================================================

This folder is the backend engine for a Tamil Nadu-wide government tender
monitoring app. It was built with Claude in the web app, on a machine that
could NOT reach the live portal — so one part (the scraper) needs finishing
against the real site, which you can do because you have internet access.

Read these first, in order, so you understand the design:
  - README.md
  - docs/TN_Tender_App_Build_Spec.docx  (the full plan and data model)
  - engine/classify.py, engine/store.py, engine/scrape.py, engine/main.py

Key facts:
  - Target portal: https://tntenders.gov.in/nicgep/app (GePNIC system).
  - Coverage is Tamil Nadu-wide across five departments: MAWS, RD&PR, DTP,
    ADW, HR&CE (use HR&CE, not HRNC).
  - classify.py (dept + work-category tagging) and store.py (SQLite history
    + five event types: NEW, CORRIGENDUM, RETENDER, DATE_EXTENSION,
    CANCELLATION) are already TESTED and working. Don't rewrite them unless
    you find a real bug; refine the keyword lists if needed.
  - scrape.py is the piece to finish.

Please do this, walking me through each step and pausing when you need me:

1. Set up the environment: confirm Python 3, then install playwright and its
   chromium browser. Give me the commands; let me run them.

2. Run `python3 engine/scrape.py --probe`. Open the saved data/page.html and

   actual results table looks like.

3. Fix the SELECTORS block and the row-parsing in engine/scrape.py so it
   reliably returns real tenders statewide. Aim for the browse route that

   advanced-search date filter is usually most complete). Correctly fill:
   title, organisation, district, local_body, estimated amount, published
   and closing dates, EMD, tender fee, doc/apply links, and status.
   Note: Mayiladuthurai tenders sometimes sit under Thanjavur/Nagapattinam
   circles — keep district and local_body as separate fields.

4. Run `python3 engine/main.py` end to end and confirm real tenders land in

Constraints:
